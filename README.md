# SecretSift

**A secret scanner that knows the difference between a real key and a placeholder, plus a benchmark so you can check that claim yourself.**

Most scanners flag every hash, UUID and `your_api_key_here`. People learn to ignore them, and then the real leak slips through.
SecretSift extracts candidates with patterns and entropy, then a small ML model uses the value *and its context* to decide if it is a real secret. Every finding comes with a reason.

## Install and use

```bash
pip install -e .
secretsift scan .                              # scan a folder
secretsift scan . --format sarif --out s.sarif # GitHub code scanning
secretsift scan . --history                    # secrets added anywhere in git history
secretsift scan . --write-baseline .baseline.json   # adopt on an old repo, flag only NEW secrets
secretsift scan . --baseline .baseline.json
secretsift scan . --mode rules                 # patterns only (no ML)
```

Exit code is 1 when something is found (CI friendly); use `--exit-zero` to report only. Secrets are never printed in full.

## Features

- Context-aware ML filter (25 value/context features + TF-IDF of the masked line), explanations for each finding
- Git history scan, baselines, SARIF output, pre-commit hook (`.pre-commit-hooks.yaml`), GitHub Action (`action.yml`)
- FastAPI service: `python manage.py serve` then `POST /scan`
- Built-in benchmark: `secretsift bench build && secretsift bench run`, compares against `detect-secrets` and two ablations

## How it works

```
file -> candidates (provider patterns | secret-like assignment | high entropy)
     -> features (entropy, charset, hash/UUID/placeholder signals, variable name, path, masked context)
     -> classifier (best of logistic regression / gradient boosting / MLP on validation PR-AUC)
     -> threshold -> finding + reasons
```

## Honest limitations

Synthetic secrets, Python-heavy negatives, lower recall on formats never seen in training, no live key verification. Rotate any real secret you find.
